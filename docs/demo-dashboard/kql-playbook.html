Secrets Exfiltration Monitor

Detects high-volume Key Vault secret, key, or certificate read/list activity and backup operations from the same account and IP address. 

// Tactic: Credential Access | Technique: T1552
let Lookback = 1d;
let Window = 15m;
let SecretOperationThreshold = 20;
let VaultThreshold = 2;
  • Default tuning: SecretOperationThreshold = 20, VaultThreshold = 2, Window = 15m.
  • Expected entities: map AccountName to Account and IPAddress to IP.
  • False positives: backup jobs, deployment pipelines, certificate renewal, inventory scripts, or incident response collection.
  • Response: restrict identity, rotate affected secrets, review Key Vault RBAC, and add allowlists only for approved automation.

SecurityAlert Substitute Evidence

Rule runs Preview did not have records yet, so the lab uses SecurityAlert as proof that the scheduled analytics rule created alerts. 

SecurityAlert
| where TimeGenerated > ago(24h)
| where AlertName == "AZZT - Key Vault Secrets Exfiltration Monitor (dev)"
| project TimeGenerated, AlertName, AlertSeverity, Status, ProviderName, SystemAlertId
| order by TimeGenerated desc

Validation Checklist

  • Confirm AzureActivity is connected for subscription activity.
  • Enable Key Vault diagnostic settings before relying on the secrets monitor.
  • Run each KQL file in Logs with the expected time range.
  • Confirm each query returns TimeGenerated, AccountName, IPAddress, Action, and Severity.
  • Create scheduled analytics rules only after each query has been validated.
  • Track alert, incident, triage, assignment, and closure timestamps for response measurement.
