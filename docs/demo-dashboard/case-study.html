Azure Zero Trust DevSecOps Case Study

A secure Azure delivery lab covering CI/CD security gates, GitHub OIDC validation, Bicep what-if, Azure Policy governance, Microsoft Sentinel, and live KQL detection testing.

Scope

  • GitHub Actions CI security gates for secrets, SAST, container, IaC, and MSDO.
  • GitHub Actions CD authentication to Azure through OIDC federation.
  • Azure Bicep build and subscription-level what-if validation.
  • Azure Policy assignment in DoNotEnforce mode for dev.
  • Microsoft Sentinel onboarding backed by Log Analytics.
  • Azure Activity diagnostic ingestion into Log Analytics.
  • Key Vault AuditEvent ingestion and KQL detection validation.
  • Scheduled Sentinel rule, alert evidence, and incident lifecycle closure.

Architecture And CI/CD Evidence

The dev environment includes a workload resource group, Log Analytics workspace, Sentinel onboarding, a virtual network, and three NSGs. The policy baseline is assigned at subscription scope in audit-style dev mode.

Sentinel And KQL Validation

AzureActivity and Key Vault diagnostics were validated with real Log Analytics rows. A temporary Key Vault generated controlled secret access telemetry, the KQL rule produced High severity output, and a scheduled Sentinel analytics rule generated SecurityAlert rows and incident 1340.

Accepted Limitations And Tradeoffs

  • Entra ID SigninLogs and AuditLogs are blocked by university tenant permissions.
  • Defender Standard plans are deferred as a cost-conscious lab tradeoff.
  • Conditional Access automation remains a production hardening step.
  • Rule runs Preview had no records yet, so SecurityAlert rows are used as substitute evidence.
  • Raw incident and alert screenshots remain in reports/ and must be redacted before public use.
